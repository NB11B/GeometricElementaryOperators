# v0.18.1 post-merge blocker resolution

A local review of merge `2ae375672dd7fbdd4432bdcd0fa043896ea3bc5a` found correctness and ABI gaps that were not exercised by the original green matrix. They are addressed first by the isolated v0.18.2 hotfix in PR #13 and are carried forward into the v0.19 branch.

## v0.18.2 blocker fixes

- **Benchmark undefined behavior:** the selected-path fixed-point sink uses defined unsigned mixing, conversion and execution statuses are checked, and the executable is registered for sanitizer validation.
- **RTL overflow mismatch:** generated fixed-point products expose overflow, check each rounded multiplication before narrowing, accumulate complete components in a wide signed type, check only the final component range, invalidate data outputs on overflow, and preserve cancellation cases accepted by fixed C.
- **Controller protocol:** generated control logic serializes dependencies, samples overflow only with operation completion, aborts on failure, keeps overflow sticky until reset/start, pulses `done` for success and abort, and pulses `result_valid` only on success.
- **Missing ABI symbols:** the archive again exports `geo_struct_program_execute` and `geo_banked_execute`; CI verifies the symbols and link-level consumer tests call both public and `_impl` names.
- **Caller-owned structure ABI:** `geo_optimized_witness_t` retains its established size and field offsets; terminal count continues to be supplied explicitly to later passes.
- **Non-finite EML input:** `geo_eml_log` rejects NaN and both infinities without modifying caller output storage.
- **Overstated benchmark labels:** the established executable name remains available, while stdout, JSON, and Markdown identify the exact selected operation/path matrix and use “specialized native C” terminology.
- **Pipeline masking:** every `vvp | tee` and `yosys | tee` validation pipeline enables shell pipe failure propagation.

## v0.19 expanded regression gate

After the v0.18.2 baseline is merged, the v0.19 candidate additionally requires:

- GCC and Clang float/double builds;
- ASan/UBSan tests plus selected-path and numerical harness execution;
- Q1, Q8, Q16, Q24, and Q30 checks for fixed arithmetic, fixed Omega, and fixed routing control;
- standalone ESP32 component and ESP32-S3 application compilation;
- CUDA Toolkit 13.x compilation for float and double, including generated CUDA schedules;
- fixed C/RTL nominal and overflow vector equivalence;
- RTL simulation and synthesis for product, controller, and executable schedules;
- reproducible workload and numerical-error artifacts.

A tag is prohibited until the required gate passes on the exact candidate commit. Compile-only CUDA and ESP32 validation are not represented as physical-device results. Hosted runner startup failures are recorded separately from executed test failures and are not accepted as passes.
