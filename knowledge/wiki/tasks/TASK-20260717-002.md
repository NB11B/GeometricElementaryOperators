# TASK-20260717-002 — Add GEO A and B runs to the ESP32-C6 IMU replay benchmark

## Original request

Take over the stalled implementation and provide the A and B GEO runs for the existing ESP32-C6 deterministic IMU replay benchmark.

## Objective

Add `A_geo_float` and `B_geo_fixed_q16` behind the same `benchmark_impl_t` interface already used by the C and D baselines, without changing the replay generator, analytic reference, metric collection, timing boundary, or output schema.

## Constraints

- Use the existing GEO kernel rather than a benchmark-only duplicate of quaternion multiplication.
- Preserve allocation-free per-sample execution.
- Keep A, B, C, and D on identical samples and deadlines.
- State the fixed-path normalization boundary explicitly.
- Keep the pull request in draft until compile and physical-device evidence are preserved.
- Record durable implementation decisions and unresolved validation work in the repository knowledge system.

## Design decision

A full quaternion is represented through two `Cl(2,0)` values using the standard complex 2 x 2 matrix representation:

```text
q = w + xi + yj + zk
A = w + y e12
B = x e1 + z e2
q -> A + iB
```

Products are evaluated with four existing GEO products:

```text
(A + iB)(C + iD) = (AC - BD) + i(AD + BC)
```

This representation is exact before floating or fixed numerical effects and avoids introducing a separate scalar quaternion-product implementation for A or B.

## Implementation

- Added `geo_filter.c` and `geo_filter.h`.
- Added the floating GEO Mahony-style path for quaternion integration and gravity-frame rotation.
- Added the checked Q16 GEO path for quaternion products, correction arithmetic, integration, and state storage.
- Made fixed arithmetic failure observable through non-finite benchmark output and `nan_count`.
- Added a 512-step startup agreement check for A, B, and C.
- Registered A and B before C and D in the common run table.
- Added the repository GEO component to the ESP-IDF project.
- Changed output hashing to named fields only so structure padding cannot corrupt determinism.
- Changed invalid quaternion scoring to a deterministic 180-degree error.
- Added an ESP-IDF 5.3.4 ESP32-C6 compile workflow and updated benchmark documentation.

## Acceptance criteria

- `GEO_AB_CHECKS,status=pass` appears before benchmark rows.
- A and B emit the exact common CSV schema.
- A and B complete 30 x 12,000 measured samples without non-finite output.
- A agrees with C within expected floating operation-order effects.
- B reports zero arithmetic failures and a bounded task error relative to C/reference.
- Every implementation uses the same 5 ms deadline and replay trace.
- Repeated runs produce stable named-field hashes.
- Free heap and largest free block do not exhibit run-to-run drift.
