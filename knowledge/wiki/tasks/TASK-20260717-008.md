# TASK-20260717-008 — Add multi-prime discovery and witness reduction

## Objective

Extend the physically validated v1 exact-search engine into a discovery layer that can generate nearby candidate statements, search them over multiple finite fields, reduce exact witnesses, and extract canonical blade-wise polynomial differences.

## Implemented

- deterministic prime-matrix expansion of an identity corpus;
- primality validation for configured fields;
- automatic deterministic one-edit mutation generation;
- mutation provenance, expression paths, and stable mutation identifiers;
- exact deterministic CPU screening before CUDA execution;
- canonical integer polynomial extraction by basis blade;
- primitive polynomial normalization and stable equivalence hashes;
- formal zero-polynomial detection;
- multi-prime result aggregation;
- exact GPU-witness reproduction on the host;
- greedy witness reduction by active coefficient count and magnitude;
- machine-readable corpus, polynomial, witness, and discovery reports;
- a CUDA discovery runner built on the physically validated v1 environment and evidence contract;
- deterministic unit tests covering polynomial extraction, compiler agreement, mutation stability, generated-corpus compatibility, and witness reduction.

## Mathematical distinction

A zero extracted polynomial is an exact symbolic identity for the declared dimension, signature, and variable grade supports. This is stronger than surviving sampled assignments.

A nonzero polynomial proves that the expressions are not universally identical in that declared structural setting. The finite-field CUDA search then finds a concrete exact witness and independently validates the generated evaluator.

Neither result automatically generalizes to undeclared dimensions, signatures, or coefficient domains.

## Default physical matrix

- primes: 65,521; 65,519; 65,497; 32,749;
- three known identities eligible for automatic mutation;
- two known false statements retained as controls;
- eight one-edit mutations per known identity;
- 116 generated finite-field statements;
- 262,144 CUDA assignments per statement;
- 1,024 exact CPU prechecks per statement;
- 4,096 deterministic mutation-classification checks before code generation.

## Acceptance gate

- v1 corpus remains unchanged and continues to pass;
- generated mutation corpus is byte-for-byte deterministic;
- each mutation records its source identity and edit operation;
- known false controls are rejected over every configured prime;
- zero-polynomial identities survive each configured finite-field sample set;
- nonzero-polynomial candidates produce exact finite-field witnesses;
- GPU witnesses reproduce exactly on the host;
- reduced witnesses remain valid;
- polynomial extraction agrees with the v1 exact evaluator on deterministic checks;
- result validator reports `VALIDATION: PASS`;
- evidence manifest and optional archive are created.

## Current boundary

The v2 discovery layer, tests, and physical runner are implemented. Local development checks validated polynomial cancellation, nonzero mutation detection, deterministic corpus generation, and witness reduction on representative statements. The complete 116-statement CUDA matrix has not yet been executed on the physical GPU.

## Next stages

1. Physically validate the default four-prime discovery matrix.
2. Cluster mutations by primitive polynomial hash and retain one representative per class.
3. Add dimension and signature sweeps for each structural variant.
4. Add characteristic-zero integer witness search seeded from reduced modular witnesses.
5. Export zero-polynomial certificates and reduced witnesses to Lean-compatible statements.
6. Move from one-edit mutations to grammar-bounded candidate generation.
7. Apply the engine to Jacobi, rotor, duality, representation, Lie-algebra, topology, and operator-family corpora.
