# TASK-20260717-006 — Carry the IMU fusion benchmark onto CUDA

## Objective

Reproduce the deterministic IMU benchmark contract on an NVIDIA GPU while preserving the sequential recurrence inside each trajectory and exposing useful parallelism across independent trajectories.

## Measurement distinction

A single 200 Hz filter stream is a latency control, not the primary GPU workload. The GPU benchmark reports resident replay throughput separately from future streaming-step, end-to-end, CUDA Graph, and persistent-kernel modes.

Kernel-only results must never be presented as end-to-end system latency.

## Required six-way target

- A0 generic GEO float;
- B0 generic GEO Q16;
- A1 generated sparse GEO float;
- B1 generated sparse GEO Q16;
- C conventional quaternion;
- D quantized TinyML fixture.

## Implemented

- Added a CUDA emitter for the same checked IMU schedule IR used by the ESP32 compiler branch.
- Added checked-in generated CUDA float and Q32 helpers.
- Added deterministic generator staleness tests.
- Added a standalone CUDA benchmark for resident-replay A1 versus C.
- Added alternating implementation order across measured runs.
- Added device metadata, kernel timing, throughput, accuracy, NaN, trace-hash, batch-hash, state-size, and device-allocation reporting.
- Added a Windows runner that captures exact commit, GPU identity, CUDA compiler, generator gates, build logs, batch-matrix output, result validation, and SHA-256 evidence manifest.
- Added a safe evidence finalizer with optional ZIP archive generation.
- Added Python bytecode-cache ignore rules.

## Physical G0 validation

Hardware and software:

- NVIDIA GeForce RTX 5070 Laptop GPU;
- compute capability 12.0;
- CUDA compiler 13.1.80;
- CUDA runtime and driver API 13.1;
- FMA disabled with precise division and square root;
- 12,000 samples per trajectory;
- 30 runs per implementation at each batch;
- batch matrix: 1, 32, 256, 1,024, and 4,096.

Validation results:

- generated A1 and conventional C produced trace hash `71a80f19` at every batch;
- batch hashes matched between A1 and C at every batch;
- hashes remained stable across all 30 runs;
- displayed mean, p95, and maximum error matched;
- zero NaNs;
- result validator returned `VALIDATION: PASS`.

Aggregate resident-kernel results:

| batch | A1 mean us | C mean us | A1 vs C | A1 samples/s | C samples/s |
|---:|---:|---:|---:|---:|---:|
| 1 | 3603.513 | 3595.253 | 0.230% slower | 3.332 M | 3.339 M |
| 32 | 3594.077 | 3604.855 | 0.299% faster | 106.888 M | 106.586 M |
| 256 | 4086.034 | 4097.414 | 0.278% faster | 752.068 M | 750.047 M |

Interpretation:

- generated A1 and conventional C are in measurement-level parity across the complete batch matrix;
- the maximum aggregate timing separation was 0.419%;
- batch 4,096 achieved approximately 0.08364 ns per sample-trajectory for A1;
- A1 throughput increased approximately 3,589x from batch 1 to batch 4,096 while kernel duration increased approximately 14.1%;
- this corresponds to approximately 87.6% scaling efficiency relative to the ideal 4,096x throughput increase;
- these are resident kernel-throughput results, not streaming or end-to-end latency claims.

### G1 — next

### G2
